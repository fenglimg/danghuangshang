- 这个项目到底有哪些“玩”的方式？

- 在每种入口文档里只保留该入口特有的配置细节

## 1. 司礼监调度模式

### 适合谁

- 想把复杂任务交给系统自动拆解的人
- 想保留“皇帝下旨 -> 朝廷执行”产品体验的人

### 你怎么用

1. 对司礼监下旨
2. 司礼监决定是否先请内阁优化
3. 内阁给出计划
4. 司礼监派给六部
5. 最终结果回到你这里

### 典型示例

```text
帮我做一个登录系统，再顺便评估下这个月 API 成本
```

### 适合展示的位置

- 首页 README 的“主玩法”
- 产品介绍页
- 对外截图/演示

### 相关文档

- [项目 README](../README.md)
- [三省流程](./sansheng-flow.md)

## 2. Discord 多 Bot 直呼模式

### 适合谁

- 想直接指挥具体部门的人
- 想把 Discord 当协作总控台的人

### 你怎么用

直接真实 mention 对应部门：

- `@兵部` 写代码
- `@户部` 做财务分析
- `@礼部` 写文案
- `@都察院` 做审查

### 优点

- 最直观
- 反馈公开可见
- 很适合团队频道协作

### 注意

- 必须是真实 mention，不是纯文本 `@兵部`
- 多 Bot 派活依赖 `<@UserId>` 映射正确

### 相关文档

- [Linux + Discord](./setup-linux-discord.md)
- [Discord Bot 创建](./setup-discord.md)

## 3. 飞书单 Bot 模式

### 适合谁

- 国内用户
- 不想维护多个机器人
- 想保留朝廷协作但不想暴露后台细节

### 你怎么用

1. 只创建一个飞书机器人：司礼监
2. 所有请求都发给司礼监
3. 司礼监在后台用 `sessions_spawn` 调度其他部门

### 用户体验

- 用户只看到一个 Bot
- 但后台仍是多 Agent 协作

### 适合展示的位置

- 国内部署方案页
- “极简上手”路线页

### 相关文档

- [Linux + 飞书](./setup-feishu.md)

## 4. 纯 WebUI 模式

### 适合谁

- 不想配 Bot
- 只想先试能力
- 想用浏览器快速验证模型和对话链路

### 你怎么用

1. 不配置 Discord / 飞书
2. 只填 LLM API Key
3. 打开 Gateway 自带 Chat 页面直接对话

## 玩法文档应该怎么显示

推荐显示结构：

### README 里怎么放

只放 4-6 个最重要入口：

- 司礼监调度模式
- Discord 多 Bot
- 飞书单 Bot
- 纯 WebUI
- GUI 管理后台
- 翰林院专题玩法

每个只写：

- 一句话说明
- 指向这页或专项页的链接

### docs 索引里怎么放

在 `docs/README.md` 增加单独一节：

- `功能总览`
- `玩法模式`
- `GUI 页面总览`
- `Skills & Extensions`

### 单页里怎么展示

每个玩法固定 4 个块：

1. 适合谁
2. 你怎么用
3. 典型示例
4. 相关文档

这样最清晰，也最适合后续继续扩展。
